he core design of this environment is a true agent sandbox utilizing gVisor, the Model Context Protocol servers are not meant to be long-running, static deployments sitting behind standard Kubernetes Services. Instead, they are ephemeral, untrusted tool executions that your agent spins up dynamically on-demand. In this highly secure, just-in-time architecture, the way your agent discovers its available servers shifts from querying active network endpoints to querying a registry of available tool images and executing them as needed.

To expose the available capabilities to your agent in this dynamic setup, you would provide the agent with a catalog of authorized MCP server container images rather than a list of active network addresses. This catalog can still be safely stored in a standard ConfigMap, but instead of containing internal URLs, it contains the metadata required to launch the tools, such as the specific container image paths, required arguments, and necessary environment variables. When the agent determines it needs to use a specific tool to complete a task, it utilizes its localized service account permissions to make a direct call to the Kubernetes API, dynamically spawning a temporary pod running that specific MCP server image. To guarantee strict security, this temporary pod must be explicitly assigned to your gVisor runtime class in the deployment manifest, isolating the tool's potentially untrusted execution from the rest of your node infrastructure.

Once the Kubernetes API successfully provisions this ephemeral sandbox pod, the agent dynamically retrieves the pod's newly assigned internal IP address to establish a temporary network connection, executes its tool requests, gathers the required context, and then actively terminates the pod to free up compute resources and close the security boundary. Alternatively, depending on the capabilities of your specific agent framework, the agent might be designed to spawn the dynamic MCP server as an isolated container directly within its own pod structure, communicating entirely over local standard input and output channels rather than relying on network ports.
